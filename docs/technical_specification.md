# 1. Описание

## 1.1. Наименование

GiveMeTeam — веб-сервис для поиска игроков и формирования игровых групп для совместной игры в многопользовательские компьютерные игры.

## 1.2. Предметная область

Сервис позволяет пользователям публиковать объявления о поиске напарников («тиммейтов»), находить подходящие объявления с помощью фильтров, отправлять заявки на участие в игровых группах и общаться в групповом чате.

Основные объекты предметной области:

- **Пользователь** — гость или зарегистрированный участник сервиса. Имеет никнейм, дату рождения и языки общения.
- **Игра** — компьютерная игра, для которой ищут партнёров. Справочник.
- **Игровой режим** — режим конкретной игры. Справочник.
- **Объявление** — публикация пользователя о поиске игроков: игра, режим, требуемый опыт, языки общения, возрастная категория, размер группы.
- **Заявка** — запрос пользователя на присоединение к группе, созданной в рамках объявления.
- **Игровая группа** — производная сущность без собственной таблицы: автор объявления плюс пользователи с заявками в статусе `accepted`.
- **Чат** — общий чат группы, привязанный к объявлению.
- **Фильтры** — параметры отбора объявлений (игра, режим, опыт, язык, возрастная категория). Отдельной сущности не имеют.

### 1.2.1. Ключевые требования к продукту

1. Низкий порог входа: регистрация минимальна, поиск доступен гостю без регистрации. После регистрации пользователю предлагается быстрый старт (см. 4.1).
2. Фокус на ключевых критериях подбора: игре, игровом режиме и уровне опыта. Дополнительные критерии (язык, возрастная категория) оформляются как раскрывающийся список дополнительных фильтров.

## 1.4. Нефункциональные требования

- Все пользовательские данные проверяются на корректность на стороне сервера.
- Все операции, изменяющие данные, выполняются с проверкой авторизации и прав доступа.
- Целостность данных обеспечивается ограничениями БД, индексами и транзакциями (раздел 2).

# 2. Данные

Схема базы данных включает одиннадцать таблиц:

- основные: `users`, `games`, `announcements`, `applications`, `messages`;
- справочники: `languages`, `game_modes`, `experience_levels`, `age_categories`;
- связующие: `user_languages`, `announcement_languages`.

Справочники заполняются начальными данными (миграциями). Изменение справочников через пользовательский интерфейс и API не предусмотрено.

## 2.1. Связи

- пользователи 1:N объявления (автор);
- игры 1:N игровые режимы;
- игры 1:N объявления;
- игровые режимы 1:N объявления;
- уровни опыта 1:N объявления;
- возрастные категории 1:N объявления;
- пользователи M:N языки (через `user_languages`);
- объявления M:N языки (через `announcement_languages`);
- объявления 1:N заявки;
- пользователи 1:N заявки;
- объявления 1:N сообщения чата;
- пользователи 1:N сообщения чата.

## 2.2. Ограничения по элементам данных

### 2.2.1. users

Зарегистрированный пользователь системы.

|Поле|Тип|Ограничения|
|---|---|---|
|`id` — идентификатор|`BIGINT GENERATED ALWAYS AS IDENTITY`|Первичный ключ|
|`nickname` — никнейм|`VARCHAR(50)`|Обязательное. Не пустое: `length(trim(nickname)) > 0`. Уникален без учёта регистра|
|`email` — электронная почта|`VARCHAR(255)`|Обязательное. Уникален без учёта регистра. Соответствует формату адреса электронной почты|
|`password_hash` — хеш пароля|`VARCHAR(255)`|Обязательное. Хранится только хеш, исходный пароль не сохраняется|
|`birth_date` — дата рождения|`DATE`|Обязательное. Не позже текущей даты. Возраст вычисляется от даты рождения и отдельно не хранится|
|`created_at` — дата регистрации|`TIMESTAMPTZ`|Обязательное. По умолчанию: `now()`|

Ограничения уровня таблицы:

- Уникальные индексы по выражениям `lower(email)` и `lower(nickname)`.
- Пароль проверяется приложением до хеширования: не менее 8 символов и не менее одного специального символа.
- Минимального возраста регистрации нет; единственное ограничение на дату рождения — не позже текущей даты. Возрастные ограничения действуют на уровне объявлений (см. `age_categories`).
- При регистрации указывается хотя бы один язык общения (см. `user_languages`); проверяется приложением.
- Удаление пользователей в первой версии не предусмотрено (удаление учётной записи — этап P2).

### 2.2.2. languages

Справочник языков общения.

|Поле|Тип|Ограничения|
|---|---|---|
|`id`|`BIGINT GENERATED ALWAYS AS IDENTITY`|Первичный ключ|
|`code` — код языка|`VARCHAR(10)`|Обязательное. Уникален (например, `ru`, `en`)|
|`name` — название языка|`VARCHAR(50)`|Обязательное. Уникально. Не пустое: `length(trim(name)) > 0`|

Ограничения уровня таблицы: `UNIQUE (code)`, `UNIQUE (name)`. Язык, на который есть ссылки, удалить нельзя.

### 2.2.3. user_languages

Языки общения пользователя (связь M:N между `users` и `languages`).

|Поле|Тип|Ограничения|
|---|---|---|
|`user_id`|`BIGINT`|Обязательное. Ссылается на `users(id)`, `ON DELETE CASCADE`|
|`language_id`|`BIGINT`|Обязательное. Ссылается на `languages(id)`, `ON DELETE RESTRICT`|

Ограничения уровня таблицы: `PRIMARY KEY (user_id, language_id)`.

### 2.2.4. games

Справочник поддерживаемых игр.

|Поле|Тип|Ограничения|
|---|---|---|
|`id`|`BIGINT GENERATED ALWAYS AS IDENTITY`|Первичный ключ|
|`code` — код игры|`VARCHAR(50)`|Обязательное. Уникален|
|`name` — название игры|`VARCHAR(100)`|Обязательное. Уникально. Не пустое: `length(trim(name)) > 0`|

Ограничения уровня таблицы: `UNIQUE (code)`, `UNIQUE (name)`. Игру, на которую ссылаются объявления или режимы, удалить нельзя.

### 2.2.5. game_modes

Справочник игровых режимов. Каждый режим принадлежит конкретной игре.

|Поле|Тип|Ограничения|
|---|---|---|
|`id`|`BIGINT GENERATED ALWAYS AS IDENTITY`|Первичный ключ|
|`game_id` — игра|`BIGINT`|Обязательное. Ссылается на `games(id)`, `ON DELETE RESTRICT`|
|`name` — название режима|`VARCHAR(50)`|Обязательное. Не пустое: `length(trim(name)) > 0`|

Ограничения уровня таблицы:

- `UNIQUE (game_id, name)` — названия режимов не повторяются в рамках игры.
- `UNIQUE (game_id, id)` — служебное ограничение для составного внешнего ключа из `announcements`.
- Режим, на который ссылаются объявления, удалить нельзя.

### 2.2.6. experience_levels

Справочник уровней опыта («новичок», «средний», «опытный»).

|Поле|Тип|Ограничения|
|---|---|---|
|`id`|`BIGINT GENERATED ALWAYS AS IDENTITY`|Первичный ключ|
|`code`|`VARCHAR(20)`|Обязательное. Уникален|
|`name`|`VARCHAR(50)`|Обязательное. Уникально. Не пустое: `length(trim(name)) > 0`|

Ограничения уровня таблицы: `UNIQUE (code)`, `UNIQUE (name)`. Уровень, на который ссылаются объявления, удалить нельзя.

### 2.2.7. age_categories

Справочник возрастных категорий объявлений («для всех» с `min_age = 0`, «14+», «16+», «18+»).

|Поле|Тип|Ограничения|
|---|---|---|
|`id`|`BIGINT GENERATED ALWAYS AS IDENTITY`|Первичный ключ|
|`code`|`VARCHAR(20)`|Обязательное. Уникален|
|`name`|`VARCHAR(50)`|Обязательное. Уникально. Не пустое: `length(trim(name)) > 0`|
|`min_age` — минимальный возраст|`SMALLINT`|Обязательное. `min_age >= 0`|

Ограничения уровня таблицы: `UNIQUE (code)`, `UNIQUE (name)`. Категорию, на которую ссылаются объявления, удалить нельзя.

### 2.2.8. announcements

Объявление о поиске игроков.

|Поле|Тип|Ограничения|
|---|---|---|
|`id`|`BIGINT GENERATED ALWAYS AS IDENTITY`|Первичный ключ|
|`author_id` — автор|`BIGINT`|Обязательное. Ссылается на `users(id)`, `ON DELETE RESTRICT`|
|`game_id` — игра|`BIGINT`|Обязательное. Ссылается на `games(id)`, `ON DELETE RESTRICT`|
|`game_mode_id` — игровой режим|`BIGINT`|Обязательное. Режим принадлежит выбранной игре (составной внешний ключ)|
|`title` — заголовок|`VARCHAR(150)`|Обязательное. Не пустое: `length(trim(title)) > 0`|
|`description` — описание|`TEXT`|Обязательное. Не пустое: `length(trim(description)) > 0`. Длина не более 2000 символов|
|`experience_level_id` — требуемый опыт|`BIGINT`|Обязательное. Ссылается на `experience_levels(id)`, `ON DELETE RESTRICT`|
|`age_category_id` — возрастная категория|`BIGINT`|Обязательное. Ссылается на `age_categories(id)`, `ON DELETE RESTRICT`|
|`max_participants` — размер группы|`SMALLINT`|Обязательное. `max_participants BETWEEN 2 AND 10`. Включает автора|
|`status` — статус|`VARCHAR(6)`|Обязательное. `status IN ('open', 'full', 'closed')`. По умолчанию `'open'`|
|`created_at` — дата создания|`TIMESTAMPTZ`|Обязательное. По умолчанию `now()`|
|`updated_at` — дата изменения|`TIMESTAMPTZ`|Обязательное. По умолчанию `now()`. Обновляется при изменении. `updated_at >= created_at`|

Языки общения объявления хранятся в `announcement_languages` (не менее одного).

Термины:

- **активное** объявление — статус `open` или `full`;
- **неактивное** — статус `closed`.

Значения статуса:

- `open` — идёт набор, заявки принимаются;
- `full` — группа набрана, заявки не принимаются;
- `closed` — объявление неактивно: закрыто автором либо создано неактивным для активации позже.

Допустимые переходы статуса:

|Из|В|Кто и при каком условии|
|---|---|---|
|`open`|`full`|Автоматически, когда число участников (включая автора) достигло `max_participants` (при принятии заявки или при уменьшении `max_participants`)|
|`open`|`closed`|Автор|
|`full`|`open`|Автоматически, когда освободилось место (заявка участника перешла в `withdrawn` или `rejected`) или автор увеличил `max_participants`|
|`full`|`closed`|Автор|
|`closed`|`open`|Автор, если у него нет другого активного объявления и он не состоит в группе (нет заявки в статусе `accepted`)|

Ограничения уровня таблицы:

- Составной внешний ключ `(game_id, game_mode_id)` → `game_modes(game_id, id)`.
- Частичный уникальный индекс `UNIQUE (author_id) WHERE status IN ('open', 'full')` — не более одного активного объявления у автора.
- У автора не более 10 объявлений в любых статусах.
- Возраст автора (по `birth_date`) не меньше `min_age` выбранной возрастной категории (проверяется при создании и активации).
- Объявление можно создать активным (`open`) или неактивным (`closed`). Неактивные объявления не ограничены правилом «одно активное», но входят в лимит 10.
- Активировать объявление (создать со статусом `open` или перевести `closed` → `open`) нельзя, пока у автора есть другое активное объявление или он состоит в группе (имеет заявку в статусе `accepted`).
- При активации все собственные заявки автора в статусе `pending` переводятся в `withdrawn` в той же транзакции.
- При переходе в `closed` все заявки объявления в статусах `pending` и `accepted` переводятся в `withdrawn`, а все сообщения чата помечаются удалёнными (`deleted_at`) в той же транзакции. Группа распускается, при повторной активации набор начинается заново с пустым чатом.
- Правила редактирования:
    - `max_participants` нельзя установить меньше текущего числа участников (автор плюс заявки `accepted`);
    - игру, игровой режим, возрастную категорию и языки нельзя менять, если у объявления есть хотя бы одна заявка в любом статусе;
    - остальные поля (заголовок, описание, требуемый опыт, `max_participants`) автор может менять в любом статусе.
- Редактировать, закрывать, активировать и удалять объявление может только его автор.
- Физически удалить объявление можно только в статусе `closed`; связанные заявки и сообщения удаляются каскадом.
- Подача новых заявок разрешена только для объявления со статусом `open`.
- Индекс `(author_id)` — подсчёт объявлений автора и список «мои объявления».
- Индекс `(status, game_id, created_at)` — выдача списка объявлений по выбранной игре.

### 2.2.9. announcement_languages

Языки общения объявления (связь M:N между `announcements` и `languages`).

|Поле|Тип|Ограничения|
|---|---|---|
|`announcement_id`|`BIGINT`|Обязательное. Ссылается на `announcements(id)`, `ON DELETE CASCADE`|
|`language_id`|`BIGINT`|Обязательное. Ссылается на `languages(id)`, `ON DELETE RESTRICT`|

Ограничения уровня таблицы: `PRIMARY KEY (announcement_id, language_id)`. Не менее одного языка у объявления проверяется приложением.

### 2.2.10. applications

Заявка пользователя на участие в группе.

|Поле|Тип|Ограничения|
|---|---|---|
|`id`|`BIGINT GENERATED ALWAYS AS IDENTITY`|Первичный ключ|
|`announcement_id`|`BIGINT`|Обязательное. Ссылается на `announcements(id)`, `ON DELETE CASCADE`|
|`applicant_id` — заявитель|`BIGINT`|Обязательное. Ссылается на `users(id)`, `ON DELETE RESTRICT`|
|`status`|`VARCHAR(9)`|Обязательное. `status IN ('pending', 'accepted', 'rejected', 'withdrawn')`. По умолчанию `'pending'`|
|`created_at`|`TIMESTAMPTZ`|Обязательное. По умолчанию `now()`|
|`updated_at`|`TIMESTAMPTZ`|Обязательное. По умолчанию `now()`. Обновляется при изменении статуса. `updated_at >= created_at`|

Допустимые переходы статуса:

|Из|В|Кто и при каком условии|
|---|---|---|
|`pending`|`accepted`|Автор объявления, только при наличии свободного места|
|`pending`|`rejected`|Автор объявления|
|`pending`|`withdrawn`|Заявитель; автоматически при закрытии объявления, при принятии другой заявки этого пользователя, при активации его собственного объявления|
|`accepted`|`withdrawn`|Заявитель (выход из группы); автоматически при закрытии объявления|
|`accepted`|`rejected`|Автор объявления (исключение участника)|

Статусы `rejected` и `withdrawn` конечные. Статус `withdrawn` не различает причину перехода (добровольный отзыв или автоматический перевод).

Ограничения уровня таблицы:

- Частичный уникальный индекс `UNIQUE (announcement_id, applicant_id) WHERE status IN ('pending', 'accepted')` — не более одной активной заявки пользователя на объявление.
- Частичный уникальный индекс `UNIQUE (applicant_id) WHERE status = 'accepted'` — пользователь состоит не более чем в одной группе.
- Не более 5 заявок в статусе `pending` у пользователя одновременно.
- Нельзя подать заявку на собственное объявление.
- Нельзя подать заявку на объявление со статусом `closed` или `full`.
- После `rejected` (в том числе после исключения из группы) повторная заявка того же пользователя на это объявление запрещена. После `withdrawn` повторная подача разрешена.
- Пользователь, состоящий в группе (есть заявка `accepted`), не может подавать заявки.
- Автор, у которого есть активное объявление, не может подавать заявки в чужие группы.
- Возраст заявителя (по `birth_date`) не меньше `min_age` возрастной категории объявления.
- Языки: у заявителя и объявления есть хотя бы один общий язык (достаточно совпадения любого).
- При `pending` → `accepted` все остальные заявки этого пользователя в статусе `pending` переводятся в `withdrawn` в той же транзакции.
- Принятие заявки допускается только при наличии свободного места; число принятых заявок вместе с автором не превышает `max_participants`. При заполнении группы статус объявления становится `full` в той же транзакции.
- Изменять статус заявки (принять, отклонить, исключить) может автор объявления; отозвать заявку — только заявитель.
- Индекс `(applicant_id, status)` — список заявок пользователя.
- Индекс `(announcement_id, status)` — список заявок объявления и подсчёт состава группы.

### 2.2.11. messages

Сообщение общего чата группы. Одно объявление — один чат.

|Поле|Тип|Ограничения|
|---|---|---|
|`id`|`BIGINT GENERATED ALWAYS AS IDENTITY`|Первичный ключ|
|`announcement_id`|`BIGINT`|Обязательное. Ссылается на `announcements(id)`, `ON DELETE CASCADE`|
|`sender_id` — отправитель|`BIGINT`|Обязательное. Ссылается на `users(id)`, `ON DELETE RESTRICT`|
|`body` — текст|`TEXT`|Обязательное. Не пустое: `length(trim(body)) > 0`. Не более 2000 символов|
|`created_at`|`TIMESTAMPTZ`|Обязательное. По умолчанию `now()`|
|`deleted_at` — дата удаления|`TIMESTAMPTZ`|Необязательное. Если заполнено, сообщение удалено (мягкое удаление) и в выдаче не показывается|

Ограничения уровня таблицы:

- Чат доступен, только пока объявление активно (`open` или `full`). Читать и отправлять сообщения могут автор объявления и пользователи с заявкой `accepted`.
- При переходе заявки в `withdrawn` или `rejected` доступ к чату пропадает сразу; ранее отправленные сообщения сохраняются.
- Редактирование сообщений не предусмотрено.
- Удалить сообщение (мягкое удаление) может его отправитель, пока у него есть доступ к чату, или автор объявления. Бывший участник удалить свои сообщения не может.
- При закрытии объявления все его сообщения помечаются удалёнными.
- Индекс `(announcement_id, created_at)` — загрузка истории чата.

## 2.3. Общие ограничения целостности

1. **Ссылочная целостность.** Все внешние ключи обязательны; правила удаления указаны в таблицах 2.2. Справочные записи, на которые есть ссылки, удалить нельзя.
2. **Уникальность.** Email и никнейм уникальны без учёта регистра; коды и названия справочников уникальны; режимы уникальны в пределах игры.
3. **Согласованность игры и режима.** Режим объявления принадлежит выбранной игре (составной внешний ключ).
4. **Вместимость группы.** Число участников (автор плюс заявки `accepted`) не превышает `max_participants`.
5. **Согласованность статусов.** Статус `full` устанавливается и снимается автоматически вместе с изменением состава группы или `max_participants`. Переходы статусов объявления и заявки ограничены таблицами переходов.
6. **Единственная группа пользователя.** Пользователь участвует не более чем в одной группе: либо как участник (одна заявка `accepted`), либо как автор активного объявления. Участник не может подавать заявки новых и активировать свои объявления; автор активного объявления не может подавать заявки. Одновременно у пользователя не более 5 заявок `pending`.
7. **Лимиты автора.** Не более одного активного и не более 10 объявлений в целом.
8. **Возрастные и языковые ограничения.** Автор и заявитель удовлетворяют `min_age` категории объявления; у заявителя и объявления есть общий язык.
9. **Права на изменение.** Объявление меняет, закрывает, активирует и удаляет только автор; статус заявки меняет автор объявления; отзывает заявку только заявитель.
10. **Доступ к чату.** Только автор и принятые участники и только при активном объявлении.
11. **Данные пользователя.** Хранится только хеш пароля; обязательны email, никнейм, дата рождения и хотя бы один язык общения.
12. **Временные метки.** `created_at` и `updated_at` заполняются автоматически; `updated_at` не меньше `created_at`.

### 2.3.1. Правила, не выражаемые через CHECK

Способ реализации: правила проверяются в транзакциях серверной части (сервисный слой) под блокировками (см. 2.4); индексы и ограничения БД служат последней линией защиты от гонок. Триггер БД используется только для автоматического обновления `updated_at`.

|№|Правило|Реализация|
|---|---|---|
|1|Допустимые переходы статусов объявления и заявки|Транзакция|
|2|Возраст автора не меньше `min_age` (создание, активация)|Транзакция|
|3|Возраст заявителя не меньше `min_age`|Транзакция|
|4|Запрет заявки на собственное объявление|Транзакция|
|5|Совпадение хотя бы одного языка заявителя и объявления|Транзакция|
|6|Заявки только на объявление в статусе `open`|Транзакция, блокировка объявления|
|7|Запрет повторной заявки после `rejected`|Транзакция|
|8|Запрет заявок участнику группы и автору активного объявления|Транзакция|
|9|Не более 5 заявок `pending`|Транзакция, блокировка строки пользователя; страховки нет|
|10|Вместимость группы и автоматический `full`/`open`|Транзакция, блокировка объявления|
|11|Не более 10 объявлений у автора|Транзакция, блокировка строки пользователя|
|12|Ограничения активации (одно активное, не участник группы)|Транзакция; страховка — частичные уникальные индексы|
|13|Автоперевод заявок в `withdrawn` при принятии, активации, закрытии|Транзакция|
|14|Ограничения редактирования объявления (`max_participants`, неизменяемые поля)|Транзакция|
|15|Доступ к чату, очистка чата при закрытии|Транзакция/приложение|
|16|Минимум один язык у пользователя и объявления|Приложение|
|17|Требования к паролю|Приложение|

## 2.4. Транзакции

Общие принципы:

- Уровень изоляции — `READ COMMITTED`; необходимые условия перепроверяются после взятия блокировки.
- Порядок блокировок во всех транзакциях един: сначала строка объявления (`announcements`), затем строка пользователя (`users`), затем заявки. Это исключает взаимные блокировки (deadlock).
- Каждая транзакция атомарна: при нарушении любого правила выполняется откат и возвращается ошибка.

|№|Операция|Шаги|
|---|---|---|
|T1|Регистрация|1) Проверить данные. 2) Вставить запись в `users`. 3) Вставить связи в `user_languages`. При нарушении уникальности — откат, ошибка «email или никнейм заняты»|
|T2|Создание объявления|1) Блокировка строки автора (`FOR UPDATE`). 2) Проверить лимит 10. 3) Проверить возраст автора. 4) Если статус `open`: проверить отсутствие активного объявления и отсутствие заявки `accepted` у автора. 5) Вставить `announcements` и `announcement_languages`. 6) Если статус `open`: перевести собственные заявки автора `pending` → `withdrawn`|
|T3|Активация (`closed` → `open`)|1) Блокировка объявления. 2) Блокировка автора. 3) Проверить статус `closed`, отсутствие другого активного объявления и заявки `accepted`, возраст. 4) Статус → `open`. 5) Собственные заявки автора `pending` → `withdrawn`|
|T4|Закрытие|1) Блокировка объявления. 2) Заявки `pending` и `accepted` → `withdrawn`. 3) Все сообщения → `deleted_at = now()`. 4) Статус → `closed`|
|T5|Подача заявки|1) Блокировка объявления (`FOR SHARE`). 2) Блокировка заявителя (`FOR UPDATE`). 3) Проверить статус `open`, не автор, возраст, общий язык, нет заявки `accepted` и активного объявления, нет `rejected` по этому объявлению, нет активной заявки на него, `pending` меньше 5. 4) Вставить заявку|
|T6|Принятие заявки|1) Блокировка объявления (`FOR UPDATE`). 2) Проверить автора, заявку `pending`, статус `open`, число участников меньше `max_participants`. 3) Блокировка заявителя. 4) Проверить, что у заявителя нет заявки `accepted` и активного объявления. 5) Заявка → `accepted`. 6) Остальные `pending` заявки заявителя → `withdrawn`. 7) Если группа набрана, объявление → `full`|
|T7|Отклонение, исключение, выход|1) Блокировка объявления. 2) Проверить права и допустимость перехода. 3) Заявка → `rejected` или `withdrawn`. 4) Если объявление было `full` и освободилось место — статус → `open`|
|T8|Редактирование объявления|1) Блокировка объявления. 2) Проверить автора и ограничения редактирования. 3) Применить изменения. 4) Пересчитать `full`/`open` при изменении `max_participants`|
|T9|Отправка и удаление сообщения|1) Проверить доступ (автор или `accepted`, объявление активно). 2) Вставить сообщение или установить `deleted_at` (отправитель или автор объявления)|

# 3. Пользовательские роли

|Наименование|Ответственность|Количество|
|---|---|:-:|
|Гость|Просмотр списка и страниц объявлений, публичных профилей, фильтрация; регистрация и авторизация|неограничено|
|Авторизованный пользователь|Все возможности гостя; управление профилем (никнейм, языки); создание, редактирование, закрытие, активация и удаление собственных объявлений; отправка и отзыв заявок; обработка заявок на свои объявления; участие в групповом чате|неограничено|

В рамках одного объявления пользователь может находиться в контекстной роли:

- **автор объявления** — управляет объявлением, заявками и чатом группы;
- **участник группы** — пользователь с заявкой `accepted`; пишет в чат, может выйти из группы;
- **заявитель** — пользователь с заявкой `pending`.

Эти роли не хранятся отдельно, а определяются по данным объявлений и заявок. Пользователь не может быть одновременно участником группы и автором активного объявления.

# 4. UI / API

## 4.1. UI

1. **Регистрация и авторизация:**
    
    - Регистрация пользователя с указанием никнейма, адреса электронной почты, даты рождения, пароля (и его повтора) и языков общения.
    - Авторизация зарегистрированного пользователя.
    - Проверка корректности введённых данных. Почта при регистрации проверяется только на формат и уникальность, подтверждение почты не требуется.
    - Отображение сообщений об ошибках при некорректных данных или неуспешной авторизации (при неуспешном входе выводится общее сообщение «Неверная почта или пароль», без уточнения, что именно указано неверно).
    - Быстрый старт: после регистрации отображается окно «Давай начнем поиск команды» с предложением выбрать игру, настроить фильтры и нажать «Поиск». Окно можно закрыть без выбора.
2. **Профиль:**
    
    - Просмотр и редактирование данных профиля (никнейм, языки общения).
    - Просмотр списка собственных объявлений и управление ими.
    - Просмотр отправленных заявок и их текущих статусов.
    - Просмотр входящих заявок по собственным объявлениям.
    - Доступность действий зависит от состояния пользователя: участнику группы недоступны подача заявок и активация объявлений, автору активного объявления недоступна подача заявок; недоступные действия скрываются или блокируются с пояснением.
3. **Верхняя глобальная панель навигации:**
    
    - Отображение на всех основных страницах.
    - Название сервиса с переходом на страницу поиска.
    - Доступ к личному кабинету авторизованного пользователя.
    - Переход к основным разделам без возврата на главную страницу.
4. **Страница поиска:**
    
    - Список объявлений с основной информацией: никнейм автора, его возраст, игра, описание (или его часть), игровой режим, требуемый опыт, текущее число участников.
    - Объявления со статусом `full` отображаются с отметкой «набрано».
    - Выбор игры и настройка фильтров; дополнительные фильтры (язык, возрастная категория) — в раскрывающемся списке.
    - Постраничный вывод.
    - Переход к подробной информации об объявлении и к публичному профилю автора.
    - Доступ к регистрации и авторизации.
5. **Страница объявления:**
    
    - Полная информация: описание, игра, режим, требования, языки общения, возрастная категория, размер группы, статус.
    - Информация об авторе и текущем составе группы.
    - Список заявок (доступен автору).
    - Отправка заявки авторизованным пользователям при соблюдении ограничений.
6. **Создание и управление объявлениями:**
    
    - Создание объявления с указанием игры, режима, заголовка, описания, требуемого опыта, языков общения, возрастной категории и размера группы; создание активным или неактивным.
    - Редактирование с учётом ограничений (см. 2.2.8).
    - Закрытие, активация и удаление закрытого объявления.
    - Отображение текущего статуса.
7. **Управление заявками:**
    
    - Отправка заявки на участие в группе.
    - Просмотр собственных заявок и их статусов.
    - Принятие и отклонение заявок автором, исключение участника.
    - Отзыв собственной заявки и выход из группы.
    - Отображение актуального состава группы и числа свободных мест.
8. **Групповой чат:**
    
    - Отображение истории сообщений, связанных с объявлением.
    - Отправка текстовых сообщений участниками, имеющими доступ к чату.
    - Удаление собственных сообщений и сообщений автором объявления в пределах предоставленных прав.
9. **Публичный профиль:**
    
    - Отображение публичной информации о пользователе: никнейм, возраст, языки общения, дата регистрации.
    - Отображение активного объявления пользователя (при наличии).
    - Email и дата рождения не отображаются.
    - Доступен гостям и авторизованным пользователям.

- Все операции, изменяющие данные, выполняются с проверкой авторизации и прав доступа.
- Серверная часть проверяет корректность входных данных и ограничения целостности из раздела 2.
- Статусы объявлений и заявок изменяются только по допустимым переходам. Статус `full` устанавливается и снимается автоматически.
- Проверка свободных мест и принятие заявки выполняются в одной транзакции с блокировкой объявления.
- Списки возвращаются постранично: параметры `page` (с 1) и `page_size` (по умолчанию 20, максимум 100). Объявления сортируются по дате создания (новые первыми), сообщения — по дате отправки (старые первыми).
- Ошибки возвращаются в формате `{ "code": "...", "message": "..." }` с HTTP-кодами:

|Код|Когда|
|---|---|
|`400`|Ошибка валидации входных данных|
|`401`|Неавторизованный запрос, неверные учётные данные|
|`403`|Недостаточно прав доступа|
|`404`|Ресурс не найден|
|`409`|Нарушение бизнес-ограничений и состояния: занятые email/никнейм, лимиты, недопустимый переход статуса, отсутствие мест, повторная заявка|

# 5. Технологии разработки

## 5.1. Язык программирования

C# (.NET 10, ASP.NET Core).

## 5.2. СУБД

PostgreSQL 18.

## 5.3. Прочее

- Серверная часть: C# + ASP.NET Core — серверная логика, обработка HTTP-запросов, API, авторизация.
- Доступ к данным: ORM Entity Framework Core (провайдер Npgsql) — связь C#-кода с PostgreSQL и управление миграциями.
- Клиентская часть: HTML + CSS + JavaScript — интерфейс сайта, карточки объявлений, формы и фильтры поиска.
- Авторизация: серверная сессия на основе cookie; пароли хранятся в виде хеша.
- Бизнес-правила и транзакции: сервисный слой серверной части (см. 2.3.1, 2.4); триггер БД — только для `updated_at`.
- Чат: получение новых сообщений периодическим опросом.

# 6. Тестирование

Виды тестирования: функциональное, модульное, интеграционное.

Что проверяется:

- регистрация и авторизация: правила пароля, уникальность email и никнейма, сообщения об ошибках;
- создание, редактирование, закрытие, активация и удаление объявлений, лимиты (1 активное, 10 всего), ограничения редактирования;
- подача и обработка заявок: все допустимые и недопустимые переходы статусов, лимит 5 `pending`, возрастные и языковые ограничения, повторная заявка после `rejected`, единственная группа пользователя;
- вместимость группы и автоматические переходы `open` ↔ `full`, в том числе при одновременных запросах (параллельное принятие заявок);
- автоматический перевод заявок в `withdrawn` при принятии, активации и закрытии;
- работа чата: доступ только автору и принятым участникам, мягкое удаление, очистка при закрытии;
- разграничение прав доступа и корректность HTTP-кодов;
- корректность взаимодействия серверной части с базой данных: ограничения, индексы, транзакции.

Тестовые данные: заполненные справочники (игры, режимы, языки, уровни опыта, возрастные категории) и набор пользователей, объявлений и заявок во всех статусах.
